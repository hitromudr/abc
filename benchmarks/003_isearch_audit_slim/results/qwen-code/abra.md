# Концептуальный Протокол: Аудит Поисковой Системы `isearch`

## 1. Топология задачи (Ontology)

- **Мета-тип:** Статический аудит распределённой системы (API + Vector DB + ML)
- **Ключевой конфликт:** Скорость индексации vs Консистентность данных

## 2. Инварианты (Invariants)

1. **Закон сохранения ID:** Детерминистичный hash → недетерминистичный `hash()` в Python
2. **Предел батча:** Qdrant имеет лимит на размер батча (500–1000 точек)
3. **Принцип изоляции:** Параллельная запись в одну коллекцию требует блокировок

## 3. Точка опоры (Leverage Point)

- **Фокус внимания:** `src/vector_store.py` → метод `upsert()` (генерация ID, батчинг)
- **Игнорируемый шум:** Красивые фичи (keyword boosting, clustering) — не решают проблему потерь данных

## 4. Векторы энтропии (Degradation Paths)

- **Анти-паттерн А:** `abs(hash(...))` для ID → коллизии удваиваются, данные перезаписываются
- **Когнитивное искажение Б:** "Один раз работало → всегда будет работать" (отсутствие телеметрии потерь)

## 5. Алгоритм стабилизации (The Protocol)

- **Фаза 0: Изоляция.** Выделить критичные компоненты (vector_store, services)
- **Фаза 1: Оцифровка.** Верифицировать каждую находку в коде (строка, функция)
- **Фаза 2: Применение рычага.** Сфокусироваться на GT-3, GT-4 (активные баги)
- **Фаза 3: Интеграция.** Сохранить отчёт в `baseline.md`

## 6. Метрика истины (Truth Criteria)

- **Состояние успеха:** Отчёт с ≥2 активными находками (GT-3, GT-4), верифицированными в коде
- **Ложный сигнал успеха:** Много находок, но все false positives или уже исправлены (GT-1, GT-2)

## 7. Эвристики и Мета-Контекст

- **Открытые вопросы:** Почему GT-3, GT-4 не исправлены после bench 001?
- **Тактические предложения:** Добавить телеметрию (логировать отклонённые батчи Qdrant)
- **Комментарии оператора:** Slim-версия abra (4 файла) — проверить, не потеряется ли глубина

## 8. Резолюция и Архитектурная Развилка (Approval Gate)

- **Фундаментальный диагноз:** Система жертвует консистентностью данных ради скорости индексации, без механизмов обнаружения потерь.

**Стратегические варианты:**

| Вариант | Подход | Плюсы | Минусы | Цена |
|---------|--------|-------|--------|------|
| **А** | Глубокий аудит (GT-3, GT-4 + поиск новых) | Найдёт корневые причины, actionable | Долго (6 фаз) | 1 сессия |
| **Б** | Поверхностный скан (только GT-сверка) | Быстро | Пропустит новые баги | Низкая ценность |

**Рекомендация ИИ:** Вариант А (бенчмарк требует глубины, GT-3/GT-4 активны).

**Ближайшие физические шаги:**
1. **[APPROVAL GATE]** Ожидание подтверждения (продолжить глубокий аудит?).
2. **[ЗАПРЕТ]** Не генерировать код исправлений до утверждения отчёта.
