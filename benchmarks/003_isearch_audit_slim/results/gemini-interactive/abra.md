# Концептуальный Протокол: Архитектурный Аудит isearch

## 1. Топология задачи (Ontology)
- **Мета-тип:** Аудит детерминированности состояния, конкурентности и контрактов API.
- **Ключевой конфликт:** Разрыв между жизненным циклом процесса (Python interpreter) и постоянным хранилищем (Qdrant), а также конфликт между CPU-bound логикой и асинхронным Event Loop.

## 2. Инварианты (Invariants)
1. **Закон сохранения Наследственности:** Идентификатор чанка в базе (Point ID) обязан быть абсолютно детерминированным и зависеть только от контента, независимо от времени и среды исполнения.
2. **Предел Метаболизма:** В асинхронном веб-сервере (FastAPI) ни одна операция в главном потоке не имеет права блокировать Event Loop дольше нескольких миллисекунд.
3. **Принцип Целостности:** Конкурентная запись в разделяемый ресурс (`_state.json`) без арбитра (lock) гарантированно ведет к порче данных (Race Condition).

## 3. Точка опоры (Leverage Point)
- **Фокус внимания:** Имплементация детерминированного хэширования в `VectorStore` и изоляция тяжелых вычислений кластеризации.
- **Игнорируемый шум:** Мелкие баги парсинга markdown или логика графов, которые не приводят к фатальной деградации состояния системы.

## 4. Векторы энтропии (Degradation Paths)
- **Анти-паттерн А (SIPHASH в БД):** Использование `hash()` для генерации Qdrant ID (`src/vector_store.py:76`). При рестарте сервера все файлы получат новые ID. Qdrant не обновит старые чанки, а создаст дубли. При удалении файлов через инкрементальную индексацию старые чанки останутся "зомби", так как их ID больше невозможно вычислить. База пухнет бесконечно.
- **Анти-паттерн Б (Event Loop Blocking):** Эндпоинт `/projects/{project_name}/clusters` (`src/main.py`) вызывает `kmeans.fit_predict` и `client.scroll(limit=10000)` синхронно. Любой вызов этого API остановит обработку всех остальных запросов ко всем проектам до завершения расчетов.
- **Анти-паттерн В (State Race Condition):** Локальный стейт `IndexStateManager` (`src/state_manager.py`) перезаписывается без блокировок. Два одновременных вызова `/projects/{name}/index` приведут к перезаписи JSON файла и потере трекинга файлов.

## 5. Алгоритм стабилизации (The Protocol)
- **Фаза 0: Изоляция.** Предупредить пользователей о необходимости полной переиндексации (reindex=True) после патча, так как старые ID несовместимы с новыми.
- **Фаза 1: Стабилизация ID (Мутация).** Заменить `hash()` на криптографический `hashlib.sha256(text.encode()).hexdigest()` с усечением до uint64, поддерживаемого Qdrant.
- **Фаза 2: Разблокировка Метаболизма.** Перенести эндпоинт `/clusters` на использование `BackgroundTasks` (возврат Task ID по аналогии с индексацией) или завернуть `KMeans` в `asyncio.get_event_loop().run_in_executor()`.
- **Фаза 3: Иммунитет Стейта.** Добавить механизм `fcntl.flock` (или кроссплатформенный аналог `filelock`) в `IndexStateManager` при чтении/записи.

## 6. Метрика истины (Truth Criteria)
- **Состояние успеха:** Перезапуск API сервера и повторная индексация того же проекта не изменяет `points_count` в коллекции Qdrant (полная идемпотентность). Вызов `/clusters` не увеличивает latency соседнего вызова `/search`.
- **Ложный сигнал успеха:** Починка только `IndexStateManager` без исправления `hash()` — база продолжит пухнуть дублями невидимо для стейт-менеджера.

## 7. Эвристики и Мета-Контекст (Heuristics & Meta-Context)
- **Открытые вопросы:** В `extract_snippet` (`src/main.py`) читается файл по пути, пришедшему из пейлоада Qdrant (`payload.get("source_file")`). Если база будет скомпрометирована (poisoned), это приведет к Path Traversal. Необходимо проверять `path.is_relative_to(project_path)`.
- **Комментарии оператора:** *(Внимание)* В текущей сессии у агента отсутствуют системные инструменты записи в файловую систему. Итоговый файл `abra.md` не был сохранен на диск автоматически. Оператору необходимо перенаправить этот вывод в файл `abra.md` вручную для успешного завершения бенчмарка.
