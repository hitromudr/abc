## 🔴 CRITICAL: 3 дефекта

### C-01 · Нестабильные ID векторов — дублирование данных при каждом рестарте

**Файл:** `src/vector_store.py`
```python
ids = [abs(hash(p.get("source_file", "") + p.get("text", ""))) for p in payloads]
```

**Причина:** В Python 3.3+ `PYTHONHASHSEED` случаен при каждом запуске процесса. `hash()` возвращает **разные значения** в разных процессах для одинаковых строк.

**Эффект:**
1. При каждом рестарте сервера `upsert` изменившихся файлов создаёт **новые ID**.
2. Старые точки с предыдущими ID **остаются** в Qdrant — удаление происходит по `source_file` filter, только для файлов в diff.
3. Hash-коллизия внутри батча (birthday paradox) — один чанк **тихо перезаписывает** другой без ошибки.
4. Коллекция бесконтрольно растёт — **утечка данных на уровне векторной БД**.

**Исправление:** `uuid.uuid5(uuid.NAMESPACE_URL, source_file + str(chunk_index))`

---

### C-02 · Race condition при параллельной индексации одного проекта

Нет блокировки от запуска двух фоновых задач для одного проекта. Обе читают один state файл, делают `delete_points_by_source()` и `upsert()` параллельно — **повреждение индекса**.

**Исправление:** Per-project `asyncio.Lock`.

### C-03 · Нет аутентификации, CORS `*`, доступ к файловой системе хоста

Любой в сети может запустить/удалить индекс, читать файлы через snippet-ы. В сочетании с `PROJECTS_BASE_DIR=..` — доступ выше корня репозитория.
